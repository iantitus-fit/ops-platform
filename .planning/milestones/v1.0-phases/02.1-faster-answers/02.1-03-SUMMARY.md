# Phase 02.1 Plan 03: Fill-ins computed from hours.md Summary

**Three new fixed-reply fill-ins (`{today_or_next_open}`, `{next_opening}`, optional `{check_in_time}`) computed by BusinessClock from hours.md at send time, with a `check_in_hours` setting (1 to 12, off by default) and a sync that refuses the check-in fill-in while the setting is off.**

## Performance

- **Duration:** about 25 min
- **Completed:** 2026-10-14T19:58:30Z
- **Tasks:** 2 (a tracer and a TDD task)
- **Files modified:** 8 (3 app, 3 test, 2 docs)

## Accomplishments
- An owner can write "he'll get back to you {today_or_next_open}" and the customer reads a time that is true when the text goes out: today if possible while the shop is open with at least 60 minutes left (inclusive), otherwise the next opening, or "when we reopen" when none is in two weeks.
- `{next_opening}` gives the next opening alone; `{check_in_time}` gives the next opening plus `check_in_hours`, capped at that day's closing, with closures skipped (Thanksgiving gives Friday).
- `check_in_hours` is optional, 1 to 12, validated in plain words; a reply using `{check_in_time}` while it is absent fails the sync naming the field. An old live version without the setting renders the next opening words, never braces.
- The unknown-fill-in sync message is now built from `REPLY_FILL_INS`, so it lists all six names and cannot drift from the list. `docs/SPEC.md` set_replies row updated.
- Tracer verified end-to-end (automated verify only): the three test files passed before Task 2 started.
