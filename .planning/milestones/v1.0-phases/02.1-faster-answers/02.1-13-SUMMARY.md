# Phase 02.1 Plan 13: Answered Close and the Easy-Part Split Summary

**A price sentence for the service a price-only draft waits on now sends and closes that draft as answered (keyed on the services code recorded, not on the model's touches flag), and a text that touches the waiting question while asking something easy gets the easy answer now, behind the faq/intake label guard and all three checks, with the partial holding line.**

## Accomplishments

- `HeldReasons::priceAlone()` reads the stored verdict (reason code, length, every code finding, the label check, and Jev's reasons plus its safety and hand-off flags). `HeldReasons::answeredBy()` walks the draft and its whole `meta.replaces` chain and answers true only when every draft was price-alone and every service the chain still waits on has a sentence in this run.
- Every message a run writes now carries `price_slugs` (services the run looked a price up for) and `price_open` (those that got no sentence). A draft whose own run sent a sentence for everything it looked up is never closed by a later sentence.
- `RunFrontDesk` treats a closing run as one with no waiting draft: it sends first, closes with `ResolveDraft::closeAsAnswered()` only when a text went out, and raises no alert. A failed send leaves W live; a draft the owner handled meanwhile is left alone.
- A draft that named no service closes only when `touches_waiting` is exactly true; on false or null the sentence still goes out and W stays live.
- `AgentReply::easyPart()` builds the easy answer as a reply of its own. `RunFrontDesk` decides it with `[faq_answer, intake_question]` and all three checks (Jev included); when it passes, its words ride in the text with the owner's sentences in front of the chosen line (partial holding, complaint or check-in), stored under the easy part's own verdict. The touching reply is stored as the fresh draft as before.

### Judgment calls inside the plan (not deviations, recorded for review)

- `price_slugs` and `price_open` are written into the shared `$attributes['meta']`, so they also land on sent agent replies and partial/check-in texts, not only on drafts. Only drafts are read; the extra keys on sent texts are harmless and no existing test pins a sent message's whole meta.
- A split needs non-blank touching words. A touching text with blank words and an easy part is left to the unchanged waiting table, because there would be no touching part to store as the fresh draft.
- A check-in that also asks something easy: the check-in line outranks the partial line, so the text is the easy words followed by the check-in line, and W stays live (no replacement draft). The plan says the line is "chosen" by priority but does not spell this combination out; the new test pins it.
- Easy words that push the combined text past 1,600 characters are dropped from it (sentences and line still go) rather than holding the whole text.
- If the owner-written send for a code-only closing run is refused for a reason other than NOT_SENT, the existing refusal path stores an empty held draft (as it did before this plan), which replaces W. A NOT_SENT failure alerts the owner and leaves W live, as the plan's test requires.
- The easy part's own hand-off reading (`asks_for_person`) is not acted on: Jev reads the same customer text for the touching reply, and the plan names only the life-safety reading.
- The life-safety test expects the stored draft reason `label:price`, not `classifier:life_safety`: the touching reply there was already held by its label, and a verdict that already holds keeps its own reason (as for the touching reply's own safety reading today).
