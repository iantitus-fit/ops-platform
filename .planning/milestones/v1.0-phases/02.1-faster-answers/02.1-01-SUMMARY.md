# Phase 02.1 Plan 01: Bookkeeping for Faster Answers Summary

**An `answered` draft resolution that refuses Send with "Already answered", six new fixed-text message kinds with a `startsWait()` set that the holding-reply check now reads, and plain words for the new hold reasons**

## Performance

- **Duration:** 5 min
- **Started:** 2026-10-14T19:43:47Z
- **Completed:** 2026-10-14T19:48:26Z
- **Tasks:** 3 (1 tracer, 2 TDD)
- **Files modified:** 13

## Accomplishments

- `ResolveDraft::closeAsAnswered($draft, $answer)` closes a held draft under a row lock: status withdrawn, resolution answered, `resolved_by` empty, words and verdict untouched, `answered_by` in meta, one `draft_answered` timeline entry shown on the card as "Draft answered". A draft that is no longer a draft is left alone and false comes back. Send and Discard on an answered draft throw exactly "Already answered" (dashboard notification tested in `DraftReviewTest`).
- `MessageKind` gained `PartialHolding`, `ComplaintHolding`, `DiscountHolding`, `CheckInReply`, `AddedInfoReply`, `CodeAnswer`, with `startsWait()` (the four wait-starting kinds) and `assembledByCode()` (the six code-assembled kinds). `SendFixedReply::holdingAlreadySent()` reads `startsWait()`; only an owner text or a draft the owner approved, edited, discarded, or code closed as answered ends the wait. Automated texts no longer end it (the old rule counted any sent non-holding reply).
- `Verdict::plainReasonFor()` reads `price:no_sentence`, `discount:no_live_offer`, `touches_waiting` and `waiting_guard:<label>` in plain words; `Verdict::hold()` and `heldFor()` accept optional owner-facing words that replace the sentence while the reason code stays the same (D-40).
- `tests/Pest.php` helpers `textsSentForAgentReplies()` and `theAgentMessage()` now leave out code-assembled texts that carry no `model_words` in `meta.parts`, decoded in PHP for SQLite and PostgreSQL parity.
- `docs/sprints/sprint-1.1.md` created with the five ROADMAP success criteria and a walk-through log line.
