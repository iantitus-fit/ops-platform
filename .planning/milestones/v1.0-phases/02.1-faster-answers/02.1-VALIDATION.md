> Per-phase validation contract for feedback sampling during execution.
> Source: `02.1-RESEARCH.md` § Validation Architecture. TDD mode is on, so each behaviour starts as a failing test.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Pest 5.3.1 on PHPUnit (`laravel/pao` agent output) |
| **Config file** | `phpunit.xml`; `tests/Pest.php` (RefreshDatabase, temp copy of `examples/example-hvac` per Feature test, scripted `FrontDeskAgent::fake()`, `FakeClassifier`) |
| **Quick run command** | `php artisan test --compact --filter=<Name>` (or a file path) |
| **Full suite command** | `php artisan test --compact` (SQLite). Postgres: `docker run --rm -d --name ops-pg-test -p 55432:5432 -e POSTGRES_PASSWORD=probe -e POSTGRES_DB=ops_test postgres:17`, then `DB_CONNECTION=pgsql DB_HOST=127.0.0.1 DB_PORT=55432 DB_DATABASE=ops_test DB_USERNAME=postgres DB_PASSWORD=probe php artisan test --compact` |
| **Estimated runtime** | ~39 seconds on SQLite (1078 tests at baseline) |

Baseline before Wave 0: SQLite 1078 passed (4454 assertions).

---

## Sampling Rate

- **After every task commit:** the narrowest file or `--filter` for the task, then `vendor/bin/pint --dirty --format agent`
- **After every plan wave:** `php artisan test --compact` (SQLite)
- **Before `/gsd-verify-work`:** full suite green on SQLite and on PostgreSQL
- **Max feedback latency:** 60 seconds
