# Phase 02.1 Plan 26: The D-46 Invariant Matrix Summary

**One Pest test runs all 1,440 possible combinations of a waiting draft, complaint, hidden hazard, price ask, blank words, check-in, pause, Jev failure, request for a person (none, keyword, agent), reply cap and agent failure through the real front desk, and the three breaches it and its probes found are fixed in RunFrontDesk with named regression rows.**

- **Duration:** 29 min

- **Completed:** 2026-10-16T23:05:00Z
- **Tasks:** 2
- **Files modified:** 3 (one created, two modified)
- **Loop time:** the 1,440-combination test takes about 37 seconds on SQLite (the whole file of 12 tests about 39 seconds). The full suite, 1,651 tests, takes about 106 seconds, so the matrix adds roughly 40 seconds and stays well under the 180-second line.

## Accomplishments

- **The harness (Task 1, tracer).** `invariantRun()` gives each combination its own customer and conversation, builds the setup for real (a waiting draft is a held run with its holding reply sent, a pause goes through `PauseConversation`, the cap is six agent texts in the last hour), scripts Jev's reading and words check and the agent, posts the text through the fake webhook and runs the queued job. `invariantBreaches()` and `invariantCheck()` check, scoped to that conversation's messages and alerts after the setup: a hazard any detector can see gets the safety line; no `safety_check_missing`; a complaint never meets an owner price or offer sentence and a complaint any detector can see reaches the owner as a complaint alert; the customer is never silent except in a paused or capped conversation (where the owner is alerted instead); at most one live draft; at most one owner-written fixed line per run and no full `holding_reply` while the earlier wait is current; the safety line is the run's first text; a check-in with a complaint gets the complaint reply, not the check-in reply; and, when Jev is down, a `safety_check_down` alert, and when every model failed, a `front_desk_failed` alert. Every failure names its flags. Seven named combinations, one per invariant, all pass.
- **The full loop (Task 2).** `holds the D-46 invariants in every combination` runs the product of the dimensions minus only the three impossible kinds (blank words without a price ask, a check-in without a waiting draft, the agent's `wants_person` when every model fails), and asserts exactly 1,440 combinations ran and none breached.
- **Jev down, every model down, hazard the keywords miss** is the one case with no safety line. The matrix checks what is possible there: the customer gets the owner's holding reply, and the owner gets `safety_check_down` and `front_desk_failed`.
- **Missing reading is outside the matrix** (Ian, 2026-10-16). The folder is live in every combination, so `safety_check_missing` is never expected (D-49). A reading that never ran (the `RunFrontDesk::reading()` fallback, or no live business folder) is covered by `ReadingRequiredToSendTest` and `JevDownTest` instead.

## Decisions Made

- **Silence while the models are down and the earlier wait is current.** D-46 says the customer is never left silent; D-51 says holding() skips a customer whose wait is current, so a second text while the models are down gets no second reply. The matrix reads both together: that one case (a waiting draft whose holding reply is still current, the agent asked, every model failed) may send nothing, because the customer already holds the owner's holding reply and the owner is alerted with `front_desk_failed`. Every other combination that is not paused or capped must send at least one text. This is a reading of two recorded decisions, not a new one; if Ian wants the customer to hear the added-info reply there, it is a one-line change in `replyWhenFrontDeskCannotAnswer()` and a tighter `silentByDesign` in the checker.
- **The agent's complaint label is a detector.** The plan's must-have says a complaint any detector could see reaches the owner as a complaint alert, and D-50 lists the agent's complaint label as one. The handoff dropped it when Jev was down.
- **Person phrase in the reading.** As the plan scripts it, Jev's reading says `asks_for_person` whenever a person is asked for (keyword or agent), so with Jev up the agent's own `wants_person` is never reached; it is reached only with Jev down. Existing handoff tests cover Jev up with the agent alone asking.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A complaint the agent labeled was dropped on a handoff**
- **Found during:** Task 2 (the full loop)
- **Issue:** With Jev down, a reply labeled complaint that also set `wants_person` (or `possible_danger` plus `wants_person`) raised only `asked_for_person`; the complaint alert was raised only from Jev's reading.
- **Fix:** `handOffToOwner()` and `alertAboutPersonAfterSafetyLine()` take `$agentFoundComplaint` and raise the complaint alert on it; the three callers (the first reply, the words-check handoff and the cover-both second reply) pass the label.
- **Files modified:** `app/Actions/RunFrontDesk.php`
- **Verification:** two named rows and the loop (18 combinations).
- **Committed in:** `fa41244` (RED `81a9d1d`)

**2. [Rule 1 - Bug] A cover-both second reply's possible_danger was never read**
- **Found during:** Task 2 (carried edge case from 02.1-21, probed with a named row)
- **Issue:** When the first reply carried no danger and only the second reply set `possible_danger`, nobody got the safety line; the customer got the added-info reply, a breach of "a hazard that any detector can see gets the safety line". The same path also lost the owner's sentences when a second-reply danger stopped them (they were neither sent nor in the draft).
- **Fix:** `askForWholeThreadReply()` sends the safety line for the second reply's `possible_danger` (or alerts about the person after the line if it also wants one), marks the stored verdict as life safety, and returns `stops`; `answerWhileDraftWaits()` holds the sentences in the draft when `stops` is set.
- **Files modified:** `app/Actions/RunFrontDesk.php`
- **Verification:** `sends the safety line when only the second reply of a cover-both run flags a danger`.
- **Committed in:** `18c7880` (RED `82d7abd`)

**3. [Rule 1 - Bug] A complaint only the second reply's words check found let the owner's price sentence ride beside it**
- **Found during:** Task 2 (carried edge case from 02.1-18)
- **Issue:** The alert was raised but the partial holding text still carried the owner's sentence, a breach of "a complaint is never answered by an owner price or offer sentence".
- **Fix:** When only the second reply is a complaint, the sentences move into the draft (pre-filled, `held_sentences`), the `price_sentences` meta is rebuilt without them, and the verdict takes the complaint reason, so the complaint reply goes out instead of the partial line.
- **Files modified:** `app/Actions/RunFrontDesk.php`
- **Verification:** `keeps the owner sentence out of the text when only the second reply of a cover-both run is a complaint`.
- **Committed in:** `18c7880` (RED `82d7abd`)

**4. [Rule 3 - Blocking] The matrix got slower with every combination**
- **Found during:** Task 2 (first full run exceeded ten minutes)
- **Issue:** Each combination fires `CustomerRecordChanged`, which queues `RenderCustomerCard` on the sync queue, and that rewrites the records folder for every customer, so cost grew with the number of customers. The shared `runQueuedFrontDeskJobs()` also re-walks every earlier job.
- **Fix:** `INVARIANT_HELD_JOBS` holds the card render back (it is not what these invariants are about) and the queue fake is replaced before each combination so only the new job is waiting. 120 combinations dropped from 16 seconds to 2; the full loop takes about 37 seconds.
- **Files modified:** `tests/Feature/FrontDesk/FrontDeskInvariantTest.php`
- **Committed in:** `81a9d1d`

**5. [Rule 3 - Blocking] The Contact factory ran out of phone numbers**
- **Found during:** Task 2
- **Issue:** `Contact::factory()` draws a unique number from only 200 fictional ones, even when the phone is overridden, so the loop failed past about 200 combinations that needed a pre-made contact.
- **Fix:** the pre-made contact for paused and capped combinations is created directly with `forceCreate`, with a comment saying why.
- **Files modified:** `tests/Feature/FrontDesk/FrontDeskInvariantTest.php`
- **Committed in:** `81a9d1d`

## Edge Cases Carried Forward

Probed with the harness or a named row, as the plan notes asked.

- **(02.1-18) After a refused combined send, the partial line retries the sentences; if that also fails, the sentences are not in the draft.** Probed with the reply lock held so every send is refused: the customer gets nothing, the draft holds the model's words without the owner's sentence, and the owner gets a `draft_waiting` alert. It breaks no D-46 invariant: a refused send is not one of the D-46 dimensions, and a held reply lock means the owner is mid-reply to that customer. **Still open**, not fixed.
- **(02.1-18) A complaint found only in the second reply of a cover-both run raises the alert but does not hold sentences riding with the partial line.** Probed, broke "a complaint is never answered by an owner price or offer sentence", **fixed here** (deviation 3).
- **(02.1-18) A check-in with a complaint reading and no sentences is unchanged.** Covered by the named combination `waiting + checkin + complaint` and the matrix's adjacency check: it gets the complaint reply, not the check-in reply, and the complaint alert. Nothing changed.
- **(02.1-21) The second agent call of a cover-both or whole-thread run does not read possible_danger.** Probed, broke "a hazard gets the safety line", **fixed for the cover-both path** (deviation 2). **Still open for the blank-words whole-thread path** (`answerTouchingWithWholeThreadDraft`), from reading the code and not from a harness run: it sends the owner's sentences with the partial line before it asks the second question, by design, so a danger (or a complaint) found only in that second reply is acted on, but the sentences have already gone out and the safety line would follow them rather than lead. Reordering would delay the sentences by a model call, so it is Ian's call. The probe I tried to write for it hit the draft-answered path instead (the waiting draft named no service, so the sentence closed it), so I did not confirm the order with a run.
