## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The D-46 matrix did not finish on PostgreSQL**
- **Found during:** Task 3 (the PostgreSQL run of the whole suite)
- **Issue:** `FrontDeskInvariantTest`'s single test runs 1,440 combinations inside the one transaction Pest wraps around every test. On PostgreSQL the planner keeps plans made for tables it still reads as empty, so low-selectivity indexes and sequential scans got slower with every combination. The file ran past 35 minutes in the first attempt and was still at about 1,260 of 1,440 combinations after about 55 minutes in the second, slowing all the time. Plan 02.1-26 had noted that PostgreSQL was never run for it. Running `ANALYZE` inside the loop and truncating the outage table instead of deleting from it were both tried and did not help; they were reverted.
- **Fix:** run the same combinations as eight dataset slices of 180 (`array_chunk` plus `->with(...)`), each its own test and transaction. The count check now reads `INVARIANT_SLICE_SIZE * INVARIANT_SLICES` so a changed list of combinations fails loudly.
- **Files modified:** `tests/Feature/FrontDesk/FrontDeskInvariantTest.php`
- **Verification:** the file passes alone on SQLite (19 tests, 36 s) and on PostgreSQL 17 (19 tests, about 6 min); the whole suite then passes on both (1659 tests).
- **Committed in:** `59873be` (named for plan 02.1-26, whose test it touches)
