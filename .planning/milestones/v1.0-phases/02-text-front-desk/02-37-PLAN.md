<objective>
Finish G-02-1.2: move the remaining readers of message time onto the send time 02-36 introduced, and fix the latent ordering bug its diagnosis found on the same relation.

- `SendFixedReply::holdingAlreadySent()` (line 97) asks `messages()` for `latest('id')`, but the relation already orders oldest first, so the query compiles to `order by created_at asc, id asc, id desc` (now `coalesce(sent_at, created_at) asc, id asc, id desc`) and returns the oldest holding reply. A conversation with two holding replies can then send a third.
- `RunFrontDesk::replyCapReached()` (lines 245-246) counts texts by created_at, so an approved draft sent hours after it was written counts at its draft time. Decision (G-02-1.2 review): count by when the text went out, because the cap limits texts the customer received in the window.
- `RecordsWriter::waitingSince()` labels "replied <time>" with created_at.

Purpose: the holding reply, the reply cap and the owner's open-leads summary all read the same "when" as the thread.
Output: three fixes, each with a test written first, and one walk-through log line.
</objective>
