### How custom views get styled (U-01, PROJECT.md open item 1)

What is installed today: `resources/css/app.css` imports Tailwind 4.3.3 (`@import 'tailwindcss'`), built by `@tailwindcss/vite` through `laravel-vite-plugin` 3.2.0. Only `welcome.blade.php` loads it. The Filament panel has no `viteTheme` and loads its own compiled CSS. The only layout, `layouts/app.blade.php`, is the Dev chat shell and uses an inline `<style>` and `style=""` attributes; it does not load Vite.

Decision:

- Customer pages load `resources/css/app.css` and `resources/js/app.js` through a **new** layout (suggested `resources/views/layouts/customer.blade.php`) that emits `@fonts` and `@vite([...])`, as `welcome.blade.php` already does. The booking Livewire component names it with `#[Layout('layouts.customer')]`.
- `layouts/app.blade.php` and Dev chat are left exactly as they are (a local dev tool, out of scope; 02.1 D-48 holds styling). Phase 8 adds no inline style to them either.
- No Filament theme CSS is created and the panel is not touched. The two worlds never share a stylesheet.
- `resources/css/app.css` gains only the `@theme inline` tokens below and one small `@layer base` block (focus ring, and the `<summary>` marker hidden for Safari). Everything else is utilities in the Blade markup.
- **No `style=""` attribute and no `<style>` block on any new view.** A Pest architecture or grep test enforces this (see "Contract checks").
- After editing `app.css` or Blade classes, the executor runs `npm run build` (CLAUDE.md, Frontend Bundling) so the Vite manifest has the new files.

## Booking Page Contract (customer, phone-first)

### Route and shell

- `GET /book/{token}` named `booking.show` (path is the planner's), `Route::livewire`, `throttle:booking` (numbers at plan time, D-11, `throttle:leads` precedent). `CONTEXT D-11`.
- `<html lang="en">`. `<meta name="viewport" content="width=device-width, initial-scale=1">` with no `maximum-scale` and no `user-scalable=no` (zoom must work, criterion 6).
- `<meta name="robots" content="noindex, nofollow">` and `<meta name="referrer" content="no-referrer">` (U-16).
- `<meta name="color-scheme" content="light">` (U-04).
- `<title>`: "Book {service} | {business}" on the picker and check steps; "Your visit | {business}" on the booked view; "{heading} | {business}" on a dead end. `CONTEXT D-13` (page shows business name and service, never the customer's name, phone or address).
- Landmarks: `<header>` (business name), one `<main>`, `<footer>`. Exactly one `<h1>` per state. No skip link: the header holds nothing focusable and the page is a single short column, so landmarks and headings satisfy WCAG 2.4.1.
- `<noscript>`: "This page needs JavaScript to show times. Text {business} at {number} to book." (U-17)

### Page states

One Livewire component; the state is a single value. Same shell in every state.

| State | When | What the customer sees |
|-------|------|------------------------|
| Picker | Valid link, service bookable, at least one open time, nothing booked yet | h1 "Book {service}", zone line, the day list (below). |
| Check | A time has been tapped | h1 stays; h2 "Check your time", a service/day/time list, the two buttons. |
| Booked | The link has a booking (just made, or opened again later), appointment booked, and the expiry limit below has not passed | h1 "You are booked", service/day/time list, how to change (text the business). |
| Booked, cancelled or done | The link's appointment is cancelled or done, and the expiry limit below has not passed | h1 "This visit was cancelled" or "This visit is done", one line. Never offers times (D-13). |
| No times | Valid link, service bookable, no open time in the range | h1 "No times are open", one line. |
| Service unavailable | Service file gone or `book_online` now false, or the room is off (D-02) | h1 "We cannot book this online", one line. |
| Expired | Link past its expiry and either has no booking, or its visit's end time (start plus service length) has passed, whatever the visit's state (U-14) | h1 "This link has expired", one line. |
| Replaced | A newer link exists for this conversation | h1 "This link was replaced", one line. |
| Does not work | Revoked or unknown token | h1 "This link does not work", one line. |
| Rate limited | `throttle:booking` trips | h1 "Please wait a moment", one line (U-19). |
| Taken | A tap or Book finds the time taken (D-07) | Picker again with fresh times and an error line above them. |
| Failed | Anything unexpected on Book | Picker or Check kept; error line above the buttons. |

Expiry limit (U-14, amended by Ian): before the link's expiry, a link with a booking always shows the booked, cancelled or done view. Past the link's expiry it shows that view only until the visit's end time; after that it shows the expired page. A link still books at most once (D-13).

Dead-end pages carry the same header and footer, no picker, and `profile.phone` as an `sms:` link inside the one line (U-12).

### The picker (U-06, amended by Ian)

Days are shown as a vertical list of native disclosures, because 14 days of hourly starts can be close to 100 buttons (D-09) and a phone should never present all of them at once.

- One `<details>` per day that has at least one open time (D-09), earliest first. Its `<summary>` holds the day, "Tuesday, November 3" (`l, F j`), and a trailing chevron icon (decorative, turns when open). The browser exposes the summary as a control with its expanded state, so no `aria-expanded` or script is needed.
- The **earliest day is open on arrival** (`open` on the first `<details>`), so a customer sees times without a tap. More than one day may be open at a time; opening a day closes nothing. This matches the footer's native disclosures (U-15).
- No heading inside `<summary>`: a summary is exposed as a button and its heading semantics are not reliable across screen readers. The day name is in each time's accessible name (U-10), so nothing is lost.
- Which days are open survives a Livewire re-render (for example after "Choose a different time" or a taken time). The mechanism is the planner's (for example `wire:ignore.self` on each `<details>`, or the component remembering open days); the behavior is the contract.
- Inside an open day: a `<ul>` of `<li><button>` time buttons, two columns up to 639 px wide, three from 640 px, 8 px gap.
- A time button shows the time (`g:i A`, "10:00 AM", non-breaking space before AM/PM). Its accessible name is "10:00 AM, Tuesday, November 3" (U-10, visually hidden text inside the button). No `aria-label` is used, so Label in Name (WCAG 2.5.3) holds.
- Only start times offered by availability appear (BOOK-01, D-06 to D-11). Nothing in the markup is computed from the phone's clock or zone (D-11).
- The page never mentions the buffer, the lead time or the capacity (D-08).
- Focal point (U-35): the h1 on arrival, then the open day's times.

### The check step (U-07)

Tapping a time replaces the picker (not stacks below it) with:

- h2 "Check your time" (focus lands here, `tabindex="-1"`).
- A `<dl>`: Service, Day ("Tuesday, November 3, 2026"), Time ("10:00 AM"), and under it the zone line.
- Primary button "Book this time", full width on phones. It is the step's focal point (U-35).
- Secondary button "Choose a different time", full width on phones, below it.
- An error line, when present, sits directly above the two buttons and is referenced by the primary button's `aria-describedby`.

### The booked view

- h1 "You are booked" with a decorative check icon; focus lands on the h1 (`tabindex="-1"`) after a booking made in this visit (`CRITERION 6`). On a fresh page load of a booked link, no focus move.
- A `<dl>`: Service, Day, Time, and the zone line.
- One line: "Need to change this visit? Text {business} at {number}." (D-32). The number is an `sms:` link.
- Never a button that offers times (D-13), and no Cancel button in Phase 8 (D-32).

|---------|---------|-------|------------------|----------------|----------|

### Errors (criterion 6: errors are text beside the field)

The page has no text field. The controls that can fail are the time buttons and "Book this time", so the error is text placed directly beside them:

- The error is a short paragraph with a leading decorative exclamation-circle icon, `danger` text, directly **above the time list** (Taken) or directly **above the two buttons** (Failed).
- It is not a toast, not a banner at the top of the page, and not color alone.
- It is focusable (`tabindex="-1"`) and receives focus when it appears, so a keyboard or screen reader user lands on it. It does not use `role="alert"`, to avoid being announced twice.
- The list or button it concerns references it with `aria-describedby`.
- Taken: the picker re-renders with fresh times (D-07), the earliest day with a time open, and the line "That time was just taken. These times are open now."

### Focus and announcement map (U-09)

| Event | Focus goes to | What a screen reader hears |
|-------|---------------|----------------------------|
| Page load | Normal start of the document | Page title, then h1 |
| Open or close a day | Stays on that day's summary | "Tuesday, November 3, expanded" (the browser's native disclosure announcement) |
| Tap a time | The "Check your time" h2 | "Check your time, heading level 2", then the list on arrow |
| Choose a different time | The time button that was tapped (its day stays open) | "10:00 AM, Tuesday, November 3, button" |
| Book this time, success | The "You are booked" h1 | "You are booked, heading level 1" |
| Time just taken | The error line | "That time was just taken. These times are open now." |
| Book fails for another reason | The error line | "Your time was not booked. Try again, or text ..." |
| Link problem | n/a (the page loads in that state) | Title, then the h1 |

Mechanism (the planner's): `x-init="$el.focus()"` on the element that appears, or a Livewire browser event; the behavior above is the contract.

### Reduced motion, forced colors, zoom

- Motion: the only motion is the chevron turning (`group-open:` rotate). Its transition is wrapped in `motion-safe:` so `prefers-reduced-motion: reduce` gets none. No auto-scroll, no animated height, no carousel, no timed content. (Reduced motion is this spec's, D-43.)
- Forced colors (Windows high contrast): all boundaries are real borders, never shadows; icons use `currentColor`; focus is an outline. The native `<details>` marker is replaced by the chevron (`list-none` on `<summary>`, `::-webkit-details-marker` hidden in the base layer).
- Zoom (criterion 6): rem units throughout; no fixed heights on text (`min-h-12` only); no horizontal scroll down to 320 CSS px (400 percent at 1280); long service and business names wrap (`break-words`). WCAG 1.4.4 (200 percent text) and 1.4.10 reflow pass by construction and are walked at UAT.

## Color

Customer page (U-02, PROJECT.md open item 2).

**How color is expressed.** Colors are semantic tokens declared once in `resources/css/app.css` inside `@theme inline`, each aliasing a variable from Tailwind's stock palette (which is defined in oklch, so no hex literal exists in the repo). Markup uses only the token utilities (`bg-accent`, `text-ink`, `border-line`). Why: (1) there is one place to rebrand when the brand pass comes (the PROJECT.md amber primary is a placeholder), (2) contrast was checked once, here, instead of per element, (3) it leaves the Filament panel and its semantic colors untouched, (4) a test can forbid raw palette names and hex in Blade. Use `@theme inline` so the aliases resolve to the palette value rather than a variable that may not be emitted; the executor confirms with the built CSS.

```css
@theme inline {
    --color-page: var(--color-white);
    --color-surface: var(--color-stone-50);
    --color-ink: var(--color-stone-900);
    --color-ink-muted: var(--color-stone-700);
    --color-line: var(--color-stone-500);
    --color-line-soft: var(--color-stone-300);
    --color-accent: var(--color-amber-800);
    --color-accent-strong: var(--color-amber-900);
    --color-on-accent: var(--color-white);
    --color-danger: var(--color-red-800);
    --color-focus: var(--color-stone-900);

    --text-body: 1rem;
    --text-body--line-height: 1.5;
    --text-heading: 1.5rem;
    --text-heading--line-height: 1.2;
    --text-display: 2rem;
    --text-display--line-height: 1.2;
}

@layer base {
    :focus-visible {
        outline: 3px solid var(--color-focus);
        outline-offset: 2px;
    }

    summary::-webkit-details-marker {
        display: none;
    }
}
```

## Decided gaps

`08-CONTEXT.md` left these open. Ian decided them on 2026-11-02.

1. **A block over an already booked appointment** is refused, with text beside the Starts field naming the booking (copy above), as hand-booking refuses an overlap.

4. **Book by hand offers every service**, including those with `book_online: false` (U-25).
5. **The reply-box line's markup** (D-20) is the planner's. The contract stays: a plain line above the reply box, tied to it by `aria-describedby`, informing and not blocking.
