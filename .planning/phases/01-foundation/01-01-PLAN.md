## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ICM folder on disk -> Loader | Owner- or AI-edited files (untrusted content and paths) enter the engine |
| icm_versions -> ActiveConfig -> engine | The only path compiled configuration takes into request/job code |
| Repository -> git history | Generated files with customer data or sync noise could be committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Information disclosure | App\Icm\Loader path handling | medium | mitigate | Finder walks only inside the configured root, skips dotfiles and VCS dirs, does not follow symlinks; relative paths are derived from Finder, never from file content; records/ excluded with an anchored regex (Task 2 tests) |
| T-01-02 | Tampering | YAML front matter parsing | high | mitigate | Yaml::parse called only with PARSE_DATETIME, never PARSE_OBJECT or PARSE_CUSTOM_TAGS, so `!php/object` tags cannot instantiate classes; arch test pins Yaml usage to the Loader |
| T-01-03 | Tampering | Runtime config reads | high | mitigate | ActiveConfig reads only the active icm_versions row; recorded Boost rule plus arch test (Yaml/Finder only in Loader) stop new code from reading the folder; a half-edited file never reaches a customer |
| T-01-04 | Denial of service | Concurrent icm:sync runs | low | mitigate | Cache::lock('icm:sync') makes a second run return Busy without writes; activation in one DB transaction |
| T-01-05 | Information disclosure | Generated records and changelog in git | medium | mitigate | Anchored .gitignore rules for examples/*/records/* and examples/*/changelog.md (D-23, D-25), verified with git check-ignore in Task 1 |
| T-01-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed by this plan (the only new dependency, giggsey/libphonenumber-for-php-lite, is installed and audited in plan 01-03) |
</threat_model>
