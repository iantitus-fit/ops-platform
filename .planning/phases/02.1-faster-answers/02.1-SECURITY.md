## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Code -> draft row | Code, not the owner, ends a draft (`answered`) | Draft status and resolution written by `closeAsAnswered` (plans 01, 13) |
| Owner dashboard -> draft row | Owner acting on a draft code already closed | Send or Discard on a closed draft (01) |
| Owner folder -> sync -> customer | Owner-written sentences, replies, leads and offers go out without Jev | Price sentences, fixed replies, offer sentences, price leads (02, 03, 04, 06, 07) |
| Customer text -> model instructions | The waiting question is quoted in the instructions, also on the second call | Cleaned customer words in "Already with the owner" (05, 14) |
| Model output -> code | Untrusted structured fields | `price_services`, `touches_waiting`, `waiting_note`, `asks_discount`, `easy_reply`/`easy_label`, reply words (05, 08, 09, 11, 12, 13) |
| Code -> customer | Code-assembled text skips Jev | Owner price and offer sentences plus fixed lines (08, 11) |
| Retried job -> customer | A retry must not send a different price | Sentence key, burst claim, send lock (09) |
| Database -> owner dashboard | Draft and offer data shown to the owner | Offer names, draft body, the "wrote again" flag (10) |
| Customer -> owner's phone | Each check-in can alert the owner | Check-in alerts (12) |
| Run -> job timeout | Two agent calls inside one `ProcessInbound` run | 150-second shared chain budget against the 300-second timeout (14); plus up to four 8-second Jev calls (17, 19) |
| Map -> future change | A stale card misleads the next change | `path:line` citations in `map/` (15, 27) |
| Phase -> next phase | What 02.2 inherits about the new data | New kinds, `answered` resolution, meta keys (16); reading fields, outage rows and new alert reasons (28) |
| Customer text -> Jev (OpenRouter) -> code | Every customer text is read before any automated send | Message text out; Jev's reading back, failures as a failed reading (17) |
| Model output and reading -> owner sentences | A complaint or danger in the text stops the owner's code-sent sentences | Reading reasons, agent label, `possible_danger` (18, 21) |
| Stored verdict -> code close | Code ends a draft only on stored evidence | Customer reading and words check on the verdict (19) |
| `touches_waiting` -> draft lifecycle | A reply that touches the waiting question never sends beside it | Whole-thread draft, `answered_by` (20) |
| Code -> owner's phone (business alerts) | Alerts with no conversation | `safety_check_down`, back-up and `safety_check_missing` texts (22, 23, 24) |
| App -> Jev health ping | Fixed fictional text every five minutes | Outage record under one lock (23) |
| Every automated path -> `OutboundSender` | The second chokepoint refuses a text without the run's reading | Gate `customer_reading`, D-49 per-part rules (24) |
| Customer text -> owner's browser; owner's taps -> send | Quoted newest text and the Send anyway control | Escaped quote, disabled-while-running buttons (25) |
| Every front-desk path -> customer | The D-46 invariants hold in every combination | 1,440-combination matrix (26) |
