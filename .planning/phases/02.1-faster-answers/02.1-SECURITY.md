## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Code -> draft row | Code, not the owner, ends a draft (`answered`) | Draft status and resolution written by `closeAsAnswered` (plans 01, 13) |
| Owner dashboard -> draft row | Owner acting on a draft code already closed | Send or Discard on a closed draft (01) |
| Owner folder -> sync -> customer | Owner-written sentences, replies, leads and offers go out without Jev | Price sentences, fixed replies, offer sentences, price leads (02, 03, 04, 06, 07) |
| Customer text -> model instructions | The waiting question is quoted in the instructions, also on the second call | Cleaned customer words in "Already with the owner" (05, 14) |
| Model output -> code | Untrusted structured fields | `price_services`, `touches_waiting`, `waiting_note`, `asks_discount`, `easy_reply`/`easy_label`, reply words (05, 08, 09, 11, 12, 13) |
| Code -> customer | Code-assembled text skips Jev | Owner price and offer sentences plus fixed lines (08, 11) |
| Retried job -> customer | A retry must not send a different price | Sentence key, burst claim, send lock (09) |
| Database -> owner dashboard | Draft and offer data shown to the owner | Offer names, draft body, the "wrote again" flag (10) |
| Customer -> owner's phone | Each check-in can alert the owner | Check-in alerts (12) |
| Run -> job timeout | Two agent calls inside one `ProcessInbound` run | 150-second shared chain budget against the 300-second timeout (14) |
| Map -> future change | A stale card misleads the next change | `path:line` citations in `map/` (15) |
| Phase -> next phase | What 02.2 inherits about the new data | New kinds, `answered` resolution, meta keys (16) |
