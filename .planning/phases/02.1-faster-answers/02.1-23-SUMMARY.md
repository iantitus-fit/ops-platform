# Phase 02.1 Plan 23: Jev Outage Mode Summary

**Jev outage detection from failed live calls and a five-minute fictional health ping, with one down alert per outage, one an hour when it flaps, one back-up alert with the customer-text count, and a distinct "missing" reading that never counts as Jev down.**

## Accomplishments

- When Jev stops answering at 2 am and three customers text, the owner gets exactly one `safety_check_down` alert at once, the first two customers get the holding reply, the customer whose text the agent marks `possible_danger` gets the safety line, and the three drafts' alerts wait for 08:00.
- `SafetyCheckStatus` keeps the outage as a table row under one cache lock: one down alert per outage, none within 60 minutes of the last, a held-back alert sent at the first failure 60 or more minutes after the last, one back-up alert naming how many customer texts arrived meanwhile, none for an outage that ended before its down alert went out.
- `PingSafetyCheck` asks Jev `Hi, do you work on heat pumps?` with an empty draft every five minutes (`withoutOverlapping`), so a quiet night still surfaces an outage; with no live folder it asks nothing and changes nothing.
- A reading that never ran is now marked **missing**, not failed (Ian, 2026-10-16): the `RunFrontDesk::reading()` fallback and `ReadCustomerText` with no live business folder. The model's words hold, nothing model-written sends, `recordFailure` is never called, and `fromStored()` reads the state back as missing, distinct from failed and from absent, ready for plan 02.1-24's `safety_check_missing`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] HeldReasons treats a missing reading like a failed one**
- **Found during:** Task 1 (missing state)
- **Issue:** `HeldReasons::customerReadingFoundNothingElse()` checked only `! $reading->failed`; it was not in the plan's files_modified. A missing reading has `ran` false so it was already excluded, but the check should not depend on that.
- **Fix:** Use `! $reading->gaveNoAnswer()`.
- **Files modified:** `app/SendRule/HeldReasons.php`
- **Committed in:** `bead554`

**2. [Rule 1 - Bug] Test helper stored message times in the shop's zone**
- **Found during:** Task 2 (GREEN)
- **Issue:** The test built `created_at` with `Carbon::parse($at, 'America/Chicago')`, which Eloquent stored as Chicago wall time while `started_at` is stored in the app's UTC, so the customer-text count was 0.
- **Fix:** `safetyCheckOutageStored()` converts to `config('app.timezone')` first. Test-only; the production query was right.
- **Files modified:** `tests/Feature/SendRule/SafetyCheckOutageTest.php`
- **Committed in:** `41f0fb9`

### Plan interpretation notes (not fixes)

- **The reading() fallback is unreachable through `RunFrontDesk::handle()`**, which always assigns the reading from `ReadCustomerText` before use. The test invokes the private `reading()` by reflection, then runs the resulting reading through `DecideSendOrDraft::decide()` and asserts the hold, no outage, no alert and nothing sent.
- **With no live folder, the full run never stores a reading**: `RunFrontDesk` stops at the missing agent file with `NoActiveVersion`, which `ProcessInbound` catches. The test texts with no folder live and asserts nothing is sent, no classifier call, no outage and no alert; it then calls `ReadCustomerText::handle()` directly and round-trips its array through `fromStored()` as the "stored" reading. Plan 02.1-24 raises `safety_check_missing` from `RunFrontDesk`, where the stop happens.
- **The no-folder reason is lowercased inside a sentence**: "The customer text was not read: no business folder is live, so the safety check has no questions to ask." Plan 02.1-24's tests match `no business folder is live`.
- The `PingSafetyCheck` skeleton in the RED commit (see TDD Gate Compliance).
