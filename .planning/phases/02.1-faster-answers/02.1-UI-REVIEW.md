## Top 3 Priority Fixes

1. **Needs you card has no visual hierarchy** (`conversation-thread.blade.php:3-30`). The most urgent row (the wrote-again badge and quote) sits in the same plain flow as the hold reason and the "assistant wrote" text. On a phone the owner scans five rows to find the decision. Fix: give the section `icon` and `color="warning"` when `customerWroteAgain`, put the badge directly under the heading, and keep the Send/Discard row visually separated.
2. **Hardcoded red remains** (`business-folder.blade.php:41,54,81`; `conversation-thread.blade.php:34,97`). Ignores dark mode and Filament's palette, and a stale offer is a warning, not an error. Fix: `text-danger-600 dark:text-danger-400` for errors, `<x-filament::badge color="warning">` for the offer warning; name the offer file and format the date "M j, Y" in `BusinessFolder.php:181`.
3. **Raw error text can reach the owner's phone** (`RunFrontDesk.php:1140` passes `$reading->error ?? '...'` as the alert "why"). `OwnerAlertText::build` prints `{who}: {why}` as is, so a technical exception string can be sent as the alert. Fix: send a fixed plain sentence (like the one at `SafetyCheckStatus.php:68`) and keep the error in the log or alert record only.

## Minor Recommendations

4. Add `role="status"` / `aria-live="polite"` to the wrote-again badge paragraph; check on a real phone that `wire:poll.5s` does not reset the textarea (WINDOWS.md entry 11, still UAT).
5. Make the bare "Send" buttons (`:88`, `:100`) distinct, e.g. "Send reply".
6. Reword the twin hold reasons to say what to do: "Held: answer your open question first" vs "Held: customer added to your open question".
7. The safety-check alerts read well and follow the plain pattern ("The safety check is not answering, so replies are held for you and customers get your holding reply."; the back-up text counts texts and points to Needs you). Keep. Check "Safety check did not run" reads clearly as a title to a non-technical owner; "Reply could not be checked" may be plainer.
8. The `Held: the safety check did not answer` reason (`classifier_failed`) does not say the owner can still send it; consider adding "Check it before sending."
9. Replace the inline `style=` attributes with Filament/Tailwind utilities when the next view is touched, and add one spacing scale (gap-2 / gap-4).
10. Bubble backgrounds are `rgba` literals (`:56-58`); use Filament color variables so dark mode contrast is not left to chance.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
Strengths:
- "Send anyway" is correct and honest: the label changes exactly when the risk does (`:38`). Discard confirm says what happens ("Nothing will be sent to the customer.").
- Quoted line reads "Customer wrote, M j, g:i a:" / badge "The customer wrote again since this draft"; "(no words)" covers empty media-only texts (`:15`, `:20`).
- `forBusiness` alerts (`OwnerAlertText.php`) are one plain line plus the dashboard link, quote nothing a customer wrote (so no link-injection risk).
- Hold reasons are all plain: "Held: no price on file for this question", "Held: no offer running today", "Held: could not send right now".
Weaknesses:
- Raw error string as alert reason (fix 3).
- Offers warning unspecific (fix 2). Bare "Send" x2. Twin hold reasons (minor 6).
- `AlertReason::plainWords` "Safety check is down" is accurate but "safety check" is never explained to the owner in the alert itself.

### Pillar 2: Visuals (2/4)
- Quoting the newest customer text next to the badge gives the owner the evidence to decide: the one real visual gain (`:11-16`).
- No icon or color on the section, no focal point; the draft textarea and its helper line are the same weight as the explanatory rows. The Offers section is a heading plus red text with no link to the file.
- Icon-only buttons: none. Badge and buttons use Filament components.

### Pillar 3: Color (2/4)
- `#dc2626`: `conversation-thread.blade.php:34`, `:97`; `business-folder.blade.php:41`, `:54`, `:81` (five).
- `rgba` literals for three bubble backgrounds (`:56-58`). Amber is shared by the Front desk bubble, the not-alerted badge and the wrote-again badge, so the "needs attention" colour is not distinct.
- Positive: badges use Filament `color="warning"` and status badge colours via `match` (`:66-71`).

### Pillar 4: Typography (3/4)
- Only default size and `font-size: 0.875rem` (five uses), `<strong>` for emphasis; one weight, two sizes. No violation, but sizes are inline rather than a class scale, and the stale-offer warning is body-size note text.

### Pillar 5: Spacing (2/4)
- 21 inline `style=` attributes in the thread view. Gap values 0.25 / 0.5 / 0.75 / 1rem, `margin-top: 1rem`, textarea `padding: 0.5rem 0.75rem` hand-set. No arbitrary Tailwind values, but no scale either.
- Thread `max-height: 60vh` with a phone keyboard open leaves little room (not verified visually).

### Pillar 6: Experience Design (3/4)
Fixed since last review:
- Send disabled and Discard disabled while either runs (`wire:loading.attr="disabled"` with `wire:target`), so double-tap is blocked (`:38-39`, `:100`).
- Discard confirms before acting. Send is relabelled "Send anyway" when the draft is stale.
- Blocked-reply state shows the reason and a disabled textarea and button (`:81-90`).
- Empty thread state exists ("No messages yet."). Validation errors shown for both textareas.
- Safety-check outages tell the owner when it went down and when it returned, with a count and where the replies are.
Remaining:
- No live region for the polled wrote-again badge (minor 4).
- The Offers warning has no action; "Already answered" is still a toast only; no distinct answered state in the owner UI.
- Loading uses disabled-only; no spinner or text change while sending.
- 375px not verified; carried to UAT.
- Registry audit: not applicable (no `components.json` registry blocks checked).
