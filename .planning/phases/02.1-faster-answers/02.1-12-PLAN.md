The waiting-draft table this plan implements (W = the live draft when the run started; R = the model's words; S = code sentences):
1. Guard = [faq_answer, intake_question] when W's label is scheduling, otherwise none (plan 02.1-13 adds the split guard).
2. Verdict on R with the guard (blank R: `holdWithoutWords` for a code hold, otherwise no verdict). Life safety and asks-for-person act exactly as today; a life-safety run sends no S and no line.
3. A code hold turns a sending verdict into a hold for that reason. A sending verdict with touches_waiting not exactly false becomes `heldFor('touches_waiting')`. Check-in (waiting_note `check_in`): when R's verdict would send but touches_waiting is not exactly false, or R is held only by the guard (`waiting_guard:<label>`), or R is blank with no code hold, W stays live and untouched; R is dropped (neither sent nor stored) and the run goes to row 4. A check-in whose R holds for a reason of its own (a code check, Jev, the label floor, a code hold) goes to row 6.
4. No verdict (blank R, S only, or a check-in's R dropped in row 3): send S, if any, with the check-in line when waiting_note is check_in (the check-in line alone when S is empty); W untouched.
5. Sending verdict: send S plus R (plus the check-in line when check_in) as one text, R's verdict on the message; over 1,600 characters it becomes `heldFor('too_long')` and goes to 6. W untouched, no alert.
6. Holding verdict: the new draft replaces W (body R, or W's body when R is blank or waiting_note is check_in, so a check-in's words never become the body), alert by the existing replacement rule, no holding reply from storeDraft; then exactly one line: complaint reason gives the complaint reply leading S; else check_in gives the check-in reply after S; else S present gives the partial holding line after S; else `holdingAlreadySent()` gives the added-info reply; else `SendFixedReply::holding($conversation, reason)` starts a new wait.
7. The check-in alert is raised when the check-in reply is the line sent: `RaiseOwnerAlert::handle($conversation, AlertReason::CheckIn, $burst->last(), 'Customer checked in')`.
