# Phase 02.1 Plan 14: Cover-both whole-thread draft Summary

**When the front desk's answer to an unrelated new question is held anyway, code asks the agent once more (inside the first call's time budget) for one draft covering both questions and lets it replace the waiting draft, falling back to the two sets of words joined so the owner never loses a question.**

## Performance

- **Duration:** about 6 min
- **Started:** 2026-10-14T21:44:24Z
- **Completed:** 2026-10-14T21:50:20Z
- **Tasks:** 2 (a tracer and a TDD task)
- **Files modified:** 7 (one created)

## Accomplishments

- `RunFrontDesk::coverBothDraft()` runs in the waiting-draft branch when the model's words were `touches_waiting === false`, are non-blank, are not a check-in, and were held (including `send_refused`). It calls the agent again with `coverBoth: true` and `budgetFrom: $run->startedAt`, decides on the second reply's words with the same label guard, and stores that as the one fresh draft under the first reply's hold reason, with meta `first_reply` and `replaces`.
- The line to the customer follows the first reply's reason (complaint reply when it held as a complaint); the alert is a complaint when either reply held as one, via a new optional `$alertReason` on `storeDraft()`.
- `RunFrontDeskAgent::handle()` gained `coverBoth` and `budgetFrom`; with `budgetFrom` every provider, the first included, must fit the budget, recorded as `skipped: not enough time left in this run`. `AgentRun` carries `startedAt`.
- `FrontDeskPrompt` adds `## Write one reply that covers both` after `## Already with the owner`, saying that for this reply only it replaces the never-mention rule.
- Fallback: out of time, every provider failing, or blank second words all produce a draft of the waiting words, a blank line, then the held reply's words. Job-timeout arithmetic is unchanged (job 300 > chain 150 + two Jev calls of about 8 + 120 margin; queue retry_after 360).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Fallback implemented with Task 1 instead of Task 2**
- **Found during:** Task 1 (GREEN)
- **Issue:** The new second call throws `FrontDeskUnavailable` whenever the model cannot answer. Many existing rows already script `touches_waiting: false` with one reply and a held verdict (for example the `waiting_guard:scheduling` rows in `EasyAnswerWhileWaitingTest`); with no fallback they would crash the job.
- **Fix:** `coverBothDraft()` returns the joined draft on `FrontDeskUnavailable` or blank words from the start. Task 2's RED therefore failed only on the budget rows (a second call that should have been skipped ran); the "every provider fails", "blank words" and "joined body" rows passed on arrival and are kept as regression coverage.
- **Files modified:** `app/Actions/RunFrontDesk.php`
- **Committed in:** `9c52a6e`

- **Fix:** Assertions use 3 and 2 with a comment; the meaning is unchanged.
- **Files modified:** `tests/Feature/FrontDesk/CoverBothDraftTest.php`
- **Committed in:** `cf91a9e`
