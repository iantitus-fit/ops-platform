## Summary

I read `RunFrontDesk`, `CustomerReading`, `ReadCustomerText`, `DecideSendOrDraft`, `HeldReasons`, `SendFixedReply`, `SendCombinedReply`, `OutboundSender`, `SafetyCheckStatus`, `PingSafetyCheck`, `RaiseOwnerAlert`, `OwnerAlertText`, `AgentReply`, the migrations and factory in full. I read the diffs since c01fa3f for the rest, traced the new run order by hand through the main flows (complaint plus price, Jev down, missing reading, close-plus-partial, check-in, whole-thread, possible_danger), and read the new tests for assertions that cannot fail.

**No critical issues.** The two criticals from the last review hold as fixed:
- CR-01: `codeHoldReason()` (`RunFrontDesk.php:1444-1455`) stops every owner sentence on a Jev complaint, the model's complaint label, a failed or missing reading, an unsure person reading, a promise label on blank words, or `possible_danger`. The sentences go into the draft pre-filled and a complaint still reaches the owner. All paths that send sentences (`sendCodeAnswer`, `sendPassingReply`, `sendPartialHolding`, `sendCheckInReply`, the whole-thread path) either run after that hold or carry a reading that the sender re-checks.
- CR-02: `HeldReasons::priceAlone()` now needs a stored customer reading that ran, did not fail and found nothing else, plus a words check that ran when there are words. `DecideSendOrDraft::decide()` now always asks Jev, vetoed or not, so the evidence exists. I could not construct a path that closes a draft on a missing check.
- WR-01 is fixed: `answeredAfter()` compares `meta.answered_by` with the wait-starter id, in PHP, and `ResolveDraft::closeAsAnswered()` always writes the id. The close-plus-partial path leaves the wait current.
- WR-04 is fixed for `touches_waiting === true`. For false or null a blank-words answer still sends beside W (see IN-09, a docs drift, not a bug).
- WR-07 is fixed: the four missing cases now have tests, and the conditional-assertion tests were split. All new tests I scanned have real assertions.

The new design is consistent: the reading is made before anything acts on it, a missing reading alerts at once and is never counted as Jev down, `OutboundSender` refuses an automated text with no reading, and a failed reading still holds model words and owner sentences but lets fixed lines through. Docs line numbers in `map/processes/answer-inbound.md` match HEAD.

What is left: one wrong-words alert the owner will actually read (WR-01), one safety field that parses fail-open (WR-02), one hold reason that is dropped and makes a draft auto-closable (WR-03), and the old warnings and infos that are untouched by the gap run.

## Warnings

### WR-01: The "safety check is back" text begins "Safety check is down:"

**File:** `app/Actions/OwnerAlertText.php:82-85`, `app/SendRule/SafetyCheckStatus.php:95`, `:120-127`
**Issue:** `OwnerAlertText::forBusiness()` always writes `$reason->plainWords().': '.$why`. The recovery alert reuses `AlertReason::SafetyCheckDown` (`plainWords()` is "Safety check is down"), so the owner's phone shows "Safety check is down: The safety check is back. 3 customer texts came in while it was down; their replies are in Needs you." The down alert is also redundant ("Safety check is down: The safety check is not answering"). The recovery alert is the one text meant to calm the owner at 3 am. `SafetyCheckOutageTest` matches on the substring "is back", and `BusinessAlertTest` only pins the down wording, so nothing catches this.
**Fix:** Let the caller set the lead. Either pass a title, `forBusiness(AlertReason $reason, string $why, ?string $title = null)` with `$title ?? $reason->plainWords()`, and send `'Safety check is back'` for the back-up alert, or add a case such as `SafetyCheckBack` (also forced urgent, and listed in `AlertReason::values()` so the sync accepts it). Add a test that asserts the recovery body does not contain "is down:".

### WR-02: The agent's `possible_danger` is parsed fail-open

**File:** `app/Ai/AgentReply.php:83`
**Issue:** `possibleDanger: ($data['possible_danger'] ?? null) === true`. This is the third danger net, and the prompt tells the model to answer true whenever it is unsure. A missing key, `null`, `"true"` or `1` all become false silently. The sibling safety field `wants_person` throws `UnexpectedValueException` when it is not a bool (`:59-61`), so the chain falls to the next model; this one does not. With Jev down the agent's flag is the only net besides the keyword list, and a model that drops the key (a schema-ignoring fallback provider, say) would leave a hazard unflagged with no trace. The fake default in `tests/Pest.php` always includes the key, so no test shows the gap.
**Fix:** Treat a non-boolean like `wants_person`:
```php
if (! is_bool($data['possible_danger'] ?? null)) {
    throw new UnexpectedValueException('The answer has no true or false for possible_danger.');
}
// ...
possibleDanger: $data['possible_danger'],
```
Add the key to the older `AgentReply` fixtures, and a test that a missing key makes the chain try the next model.

### WR-03: Blank words labelled `promise` are held as `price:no_sentence`, so a later price sentence can close the draft

**File:** `app/Actions/RunFrontDesk.php:276-284`, `app/SendRule/HeldReasons.php:63-65`
**Issue:** `codeHoldReason()` returns `label:promise` for blank words, but `handle()` only keeps that reason when there are held sentences, `agent:possible_danger` or a complaint code (line 276). With blank words, a price ask that yields no sentence (HOLD or NEEDS_ANSWERS only) and a promise label, line 282 stores the draft as `price:no_sentence` with the plain reason "Held: no price on file", and the promise is gone from the record. `priceAlone()` then passes, because `holdWithoutWords` records `checks.label.passed = null` (not false) and `checks.label.label = promise` is only consulted when `passed === false`. A later text that names the same service with `touches_waiting` true, or whose sentence covers every `price_open` slug, closes the draft as answered with no alert. The sentence is only a price; the thing the model flagged as a promise is dropped from the owner's queue. The same fall-through also hides `classifier_failed` and `classifier_unsure:asks_for_person` behind "no price on file" (safe only because `priceAlone` reads the stored reading).
**Fix:** Keep the code-hold reason whenever there is one:
```php
} elseif ($words === '' && $codeHold !== null) {
    $verdict = $this->decideSendOrDraft->holdWithoutWords($run, $customerText, $this->reading(), $codeHold, $heldSentences === [] ? $this->noPriceReason([...]) : null);
```
and have `priceAlone()` return false when `checks.label.label` is a never-on-its-own label other than price, whatever `passed` says. Add a test: blank words, label promise, one HOLD service, then a sentence for that service, and assert the draft is still live.

### WR-04: The send-rule price veto does not catch amounts spelled in words (carried from WR-02, unchanged)

**File:** `app/SendRule/CodeChecks.php:18`, `:41`, `:59-62`
**Issue:** Still present; the file is unchanged since c01fa3f. "about five thousand dollars", "five grand", "around 5k" and "eighty-nine bucks" all return no finding. The reply is then held or sent on the model's own label and Jev's price answer alone, not on the code floor D-02 promises. The gap is wider now that Jev is down for stretches (outage mode): while Jev is down these words are held anyway, but any other time the label is the only guard.
**Fix:** As written in the previous review: apply `MONEY_WORDS` and a `\d+\s?k\b` pattern within the three-word window of a price word in `findings()`, and add unit cases.

### WR-05: A sync-checked price or offer sentence can still carry an unchecked amount (carried from WR-03, unchanged)

**File:** `app/Icm/Validator.php:1152-1202`, `:894-943`
**Issue:** Still present; unchanged. "$89 plus eighty more per hour", "$89, or 120$ after hours" and "$89 plus 150 for parts, a typical fee" still pass the sync. These sentences are now the only owner words that go out with no Jev read of the words.
**Fix:** Refuse any digit run outside a `$` amount, percentage or the service name; add number-word and fraction lists.

### WR-06: `unmatchedCount()` counts every miss in the history, not the current run of misses (carried from WR-05, unchanged)

**File:** `app/SendRule/PriceSentencePicker.php:231-238`
**Issue:** Still present. The query has no lower bound, so a miss, a match and a second miss reads as two misses and the default sentence is sent with no re-ask. The docblock says earlier misses do not matter.
**Fix:** Count only the rows with `id` above the newest matched row for the same service and question.

### WR-07: A check-in draft stores the waiting body under the check-in words' verdict (carried from WR-06, unchanged)

**File:** `app/Actions/RunFrontDesk.php:553-577`
**Issue:** Still present. When check-in words are held for their own reason, `$draftWords` is `$waiting->body` but `$verdict` is the verdict of the discarded check-in words. `storeDraft()` writes both onto one row, so `label`, `gate_reason` and `gate.inputs.agent_reply` describe text that is not the body. With the new `priceAlone()` this row's `gate.inputs.agent_reply` is non-blank and its words check is read, so the close decision is made on the wrong words' evidence.
**Fix:** Store W's own gate for the kept body and keep the check-in verdict under a meta key (`check_in_reply_gate`).

### IN-09: The waiting-draft docs say a null `touches_waiting` never sends, but blank-words sentences do send beside W

**File:** `app/Actions/RunFrontDesk.php:483-486` (docblock), `:524-527`, `map/processes/answer-inbound.md` step 17

That is a reasonable rule, but it is the one row missing from the table and contradicts the docblock sentence.
**Fix:** Add a row to the table: "Has no words of its own and touches W false or null: the sentences send beside W, W stays live, no alert."

### IN-10: The sender decides what a text contains from the caller's `meta.parts`, not from the text

**File:** `app/Actions/OutboundSender.php:380-394`
**Issue:** `partsOf()` returns `[]` for any kind other than `agent_reply` or a missing kind when `meta.parts` is absent, so a path that sends owner sentences or model words under a kind such as `code_answer` or `partial_holding` and forgets `meta.parts` skips the "owner sentence needs a clean reading" and the "words check passed" rules. Today only `SendCombinedReply` writes those kinds and it always sets the parts, so nothing is wrong now. The map says a new path "cannot skip" the check.
**Fix:** Treat every kind in `MessageKind::assembledByCode()` that arrives without parts as the strictest case, the same as a missing kind.

### IN-11: The back-up and down alerts are sent inside the status lock before the outage is marked alerted

**File:** `app/SendRule/SafetyCheckStatus.php:64-71`, `:91-98`

If the SMS call outlasts the lock, a later failure sees `down_alerted_at` still null and sends a second alert; if saving throws, `underLock` reports it and the next failure sends again.
**Fix:** Save the claim first (`down_alerted_at = now()`), then send, and reset it only if the raise throws.
