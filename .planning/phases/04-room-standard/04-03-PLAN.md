<objective>
Two things the room standard promises about files. First, a room adds a new kind of file to the sync (ROOM-02, D-04): the pretend room's `pretend_note` is read, validated with plain-words errors, compiled and readable at run time, and its broken example is refused while the previous version stays live (success criterion 1). A file of a room's own type must sit in that room's folder, and anywhere else the sync refuses it naming the file and the folder it belongs in (D-04, enforced per Ian's 2026-10-22 review), in one line that also offers to add the folder or remove the file when the room's folder is absent (Ian's 2026-10-22 change, D-04 with D-10); today's types are exempt and stay where they are, by kind (D-04, D-19). Second, every file has exactly one owner (ROOM-01): a room may claim only types its code handles (D-17), never the house's files or a connector file (D-11, D-25), never a file another room already claims (D-15), every file a present room handles must be claimed, and a file owned by an absent room is refused (D-10). Last, the D-12 ownership map goes into `docs/SPEC.md` beside the folder tree, tied to code by a test (D-14).

Purpose: success criteria 1 and 2 and ROOM-01's one-owner rule, enforced as each room lands (D-15). With no real room registered, today's folder passes untouched.
Output: registered-type hooks in Loader, Validator, FolderSync and ActiveConfig; ownership and placement checks in RoomChecks; the pretend note type and example; a test-only annex room; the SPEC table and its tie test.

Affects: knowledge, customer communication, marketing, sales, operations, team (the D-12 ownership table names owners in each). `docs/BLUEPRINT.md` changes in Task 3's commit: its room standard bullet links to the new SPEC table (D-14). The D-04 placement check affects knowledge and marketing, both already named; BLUEPRINT's room standard block already says new kinds of file live in their room's folder, so it needs no edit for it, and the one SPEC sentence that says the sync now refuses one anywhere else lands in Task 2's commit with the check.
