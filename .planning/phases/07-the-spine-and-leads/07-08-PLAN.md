<objective>
Make every new lead open a project. When an inbound text or web form creates a contact, the leads room queues an open after the inbound commits, beside the shared inbound path and without editing it; the open checks the room is live and the contact is not opted out when it runs, ties the project to the conversation the lead arrived in, never opens two, and can never fail or delay the inbound.

Purpose: LEAD-05, success criteria 2 and 4, D-01, D-02, D-03, D-06 (the automatic half), D-07, D-23.
Output: OpenProject::forNewLead(), the OpenProjectForNewLead job, the hook in LeadsServiceProvider::boot(), OpenOnNewLeadTest, the one named CardInjectionTest line, the contract paragraph, BLUEPRINT Built bullets and one walk-through line.

Existing tests this plan changes (D-22, named by file and line): `tests/Feature/Records/CardInjectionTest.php:90` (`->and(headingLines($card))->toHaveCount(4);` becomes `toHaveCount(6)`: the form lead from a new number in 'quotes a note that echoes what the customer typed' now opens a project, which adds '## Jobs' and '### ... · Job 1 opened'). `:36` (the first case, no example folder, so no leads room) and `:72` (no example folder) are unchanged. The research spike ran the whole suite against a prototype of this hook and found only this line and FrontDeskBootTest.php:90 (07-06) on the D-22 list; it also showed that queuing without the queue-time room check breaks nine Queue::fake() tests (DispatchInboundTest, SweepUndispatchedTest, RenderCustomerCardJobTest), which is why the check is required. If any other existing test fails, stop and bring it to Ian.

Design note (refines research Pattern 3): research wrapped `->afterCommit()` on the dispatch in try/catch, but an after-commit dispatch pushes later, inside the commit, outside that try. Here the push itself runs inside `DB::afterCommit(function () { try { dispatch } catch { report } })`, so a failing push or a failing open on the sync queue is caught where it happens and the inbound still returns normally (D-02). A rolled-back inbound discards the callback, so nothing is queued for a contact that never existed.

Chokepoint rule (CLAUDE.md): the automatic open is code, not an agent action (D-11); no model decides it, so no checks-passed record is added. It writes only through OpenProject.

Affects: sales, customer communication, operations, safety and compliance. BLUEPRINT sections 3 and 1 get Built bullets in Task 1's feat commit, section 10 and the glance row in Task 3's.
