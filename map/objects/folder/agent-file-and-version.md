# Agent file and compiled version

**Type:** object · **Mark:** live; one field half-wired (`escalate_to`: admitted-but-unrouted, intent parked for the Owner Loop, backlog 999.5) · **Checked:** 2026-11-20 @ 57cfcfa · **Where:** `agents/*.md` in the business folder, `app/Ai/AgentFile.php:10`

**One sentence.** An agent file (`type: agent`) says who answers a channel, with which models and loading which folder files; the app never reads it from disk but from the live compiled copy in `icm_versions.compiled`.

**Why this shape.** Code reads business configuration only through `ActiveConfig`, so a sync that fails validation cannot change what the front desk does (CLAUDE.md rules). The agent is found by channel, not by path, and the validator allows one agent per channel (D-35).

## Shape

- **`possible_danger` is the third danger net.** The model is told to answer true whenever it is unsure the customer's text could describe a danger to people or the home (`FrontDeskPrompt.php:71`, `AgentReply.php:87`, schema `FrontDeskAgent.php:74`). - Folder side of price and offer sentences: the agent file does not load the offers; code reads them. A typed file kind `offer` (`Loader::TYPED`, `Loader.php:24`; handled by the marketing room since Phase 5, `MarketingServiceProvider.php:20`), in `business/offers/`, has name, slug, sentence, an `amount_cents` or a `percent`, `start_date` and optional `end_date` (`Validator.php:275-282`); the sync refuses a sentence whose dollar amount or percentage does not match the declared one, or that spells money in words, or that carries a money-shaped amount the file does not back, such as "$89 plus 150" or "$4,000 to 6,000" (`Validator.php:867-1017`, `CodeChecks::moneyWordIn`, `CodeChecks::unsignedAmountsInCents` `CodeChecks.php:186`, `spelledAmountIn` `:220`, WR-05). A service file may carry `price_sentences`, each optionally keyed to intake answers, and a `price_default` (`Validator.php:229-235`, checked at `Validator.php:1072` and `:1180`), which `PriceSentencePicker::pick` reads through `ActiveConfig::service` (`PriceSentencePicker.php:45`). `rules/replies.md` gained the owner's complaint, partial holding, check-in and added-info replies (required), a discount reply, price leads for same, higher, lower and changed, and `check_in_hours` (`Validator.php:262-274`), and the fill-ins `{today_or_next_open}`, `{next_opening}` and `{check_in_time}` (`Validator.php:56`; the last needs `check_in_hours`, `Validator.php:842`; filled at send time by `FixedReplies::render`, `FixedReplies.php:102-112`). ## Half-wired field: `escalate_to`
Admitted by the validator (`Validator.php:260`, only `owner`), stored by the sync and carried in `AgentFile::$escalateTo` (`AgentFile.php:19,45`). Nothing reads it. The hand-off to the owner is hard-wired in `RunFrontDesk::handOffToOwner` (`RunFrontDesk.php:1601`). Direction: admitted-but-unrouted. Intent: **parked** for the Owner Loop (backlog 999.5, was Phase 02.2), which lets it name a staff user (`.planning/milestones/v1.0-phases/02-text-front-desk/02-CONTEXT.md:13`, D-23, D-35; Ian, 2026-10-12). Do not build on it; wire the missing end deliberately as its own change.

## Words on this card
"Agent" means four things. This card: the **agent file**. The SDK class `FrontDeskAgent`: the **front desk agent**. `MessageAuthor::Agent`: the author of every automated text. The SDK's `agent_conversations` tables: leftover. "Version" means two things: the `icm_versions` row, which is the live compiled folder (`ActiveConfig.php:27`, `app/Models/IcmVersion.php:24`), and `gate.version` (`DecideSendOrDraft.php:77`), the shape number inside a stored verdict. They are unrelated.

## Connected to
Owned by the folder (written only by the sync, `FolderSync.php`) and, as a room, by the front desk; read by `RunFrontDesk`. Looks like it but is not: `ActiveConfig::sendingRules()` (`rules/sending.md`, an input to the send rule, not to the agent's identity) and the `records/` folder on disk, which the agent never loads.

## If you change this
**Hits:** the validator, the compile index, `AgentFile`, `FrontDeskPrompt`, `RunFrontDeskAgent`, the front desk room (`FrontDeskServiceProvider`, which handles the `agent` type, and its contract's `owns` list), the Filament Business folder page (shows name and chain, `app/Filament/Pages/BusinessFolder.php:100`), and the offer, service-sentence and reply fields above (the validator, `FixedReplies`, `PriceSentencePicker`, `OfferSentences`). A new channel needs a validator rule, a channel driver and a caller of `forChannel`. [answer-inbound](../../processes/answer-inbound.md) step 10 reads the agent and step 13 the sentences.
**Does not hit:** stored messages and verdicts (they record which model replied, in `gate.reply_model`, but are not rebuilt from the file); the send rule's thresholds (`config/gate.php`, not the folder).

## Surfaces
Writers: the owner (edits the file), the sync. Readers: `ActiveConfig`, `AgentFile`, `FrontDeskPrompt`; offers and sentences: `OfferSentences`, `PriceSentencePicker`, `FixedReplies`. External consumers: none.
