# Message and its verdict

**Type:** object · **Mark:** live · **Checked:** 2026-10-18 @ 1324f24 · **Where:** `app/Models/Message.php:44`, `app/SendRule/Verdict.php:15`

**One sentence.** A `messages` row is one text or form post in a conversation, either direction; on an automated reply it also holds the send rule's verdict: `gate_outcome`, `gate_reason` and the `gate` JSON (code name `gate*`, prose name "verdict"), which carries the run's reading of the customer's text beside the check of the agent's words.

**Why this shape.** One row carries the customer's text, or the agent's words, the owner's decision on them and the delivery, so a draft is never copied or deleted (D-54, D-28). The verdict lives on the message because it is the calibration data later tuning learns from; `gate.version` lets a new shape sit beside the old (D-07, `DecideSendOrDraft.php:70`).

Whether a draft counts as answered by a price sentence alone is `HeldReasons::answeredBy` (`HeldReasons.php:105`), which reads the stored verdict and the draft's `price_slugs` and `price_open`. The owner who then tries Send, Edit or Discard on such a draft is refused with the words "Already answered" (`ResolveDraft.php:28`, chosen at `:40` by `whyGone`, `:36-43`; the replaced and already-handled sentences sit at `:24` and `:26`).

Say "claimed" for `handled_at`; "handled" only for a draft the owner ended (`ResolveDraft.php:26`).
- `kind` is what the system sent it as (`app/Enums/MessageKind.php:8`); `label` is what the agent called its reply, one of eight words (`app/Enums/ReplyLabel.php:9`). `MessageAuthor::Agent` marks every automated text, fixed ones included (`MessageAuthor.php:8`). Besides the agent's reply, the holding, hand-off and safety lines, there are now six kinds code assembles or chooses: the partial holding, complaint, discount, check-in and added-info lines and the code answer, which is the owner's price or offer sentences sent by code (`MessageKind.php:10-31`).
- **Which kinds start a wait.** The holding reply and the partial, complaint and discount holdings tell the customer the owner will answer, so they start a wait (`MessageKind::startsWait`, `MessageKind.php:39-42`). `SendFixedReply::holdingAlreadySent` (`SendFixedReply.php:137`) finds the newest message of those kinds (`:139-143`); the wait is over only when an owner text went out after it (`:185-190`), or a draft was approved, edited or discarded since it (`:191-194`), or a draft was closed as answered by a text newer than the wait-starter (`answeredAfter`, `:212-219`). That last rule needs `meta.answered_by` to be set and newer than the wait-starter: a close with no answering id, or one made by the wait-starter itself such as the partial holding line that went out with an owner sentence, does not end the wait (WR-01; Ian, 2026-10-16, the same rule as CR-02). Automated texts, a check-in line, an added-info line, a code answer or an agent reply among them, never end it (`:134-135`). That is why a customer who texts again while the wait is current gets no second holding reply: a held text then gets the complaint reply only when it was held as a complaint and none went out in this wait yet (at most once per wait: `SendFixedReply::complaintReplyAlreadySent`, `SendFixedReply.php:161`, which asks the same question of the newest `complaint_holding` message as `holdingAlreadySent` asks of the newest wait-starter, through `nothingAnsweredSince` `:180`; D-34; Ian, 2026-10-17, G-02.1-1), otherwise the added-info line, never nothing (`RunFrontDesk.php:1556-1566`, `sendAddedInfoReply` `:947-957`, `replyWhileWaitIsCurrent` `:970-984`). `MessageKind::assembledByCode` (`MessageKind.php:50`) lists the kinds code puts together from owner sentences and fixed lines.
- **One path for code-assembled texts.** `SendCombinedReply::handle` (`SendCombinedReply.php:38`) takes the parts of one text (`ReplyParts`: an optional complaint line, the owner's sentences, the model's words that passed the send rule, one fixed line, joined in that order, `ReplyParts.php:28-36`), picks the kind from them, a check-in or added-info line ahead of the owner's sentences so that text is recorded as that reply (`ReplyParts.php:43`, `:49`, IN-01; `SendCombinedReply.php:40`), records the part names in `meta.parts` (`SendCombinedReply.php:45`, names set at `ReplyParts.php:60`), and sends through `OutboundSender` (`SendCombinedReply.php:61`). With no model words in it, the text is code's own, so it gets a fixed-reply verdict and no classifier (`:49-59`); either way the run's reading rides in its gate (`:54`, `:57-59`). `composedLength` (`:73`) measures the text as the customer would get it; over 1,600 characters (`SendOwnerReply.php:20`) the model's words are held `too_long`, kept as a draft, and the sentences go on their own with the partial holding line (`RunFrontDesk.php:371-373`, `:545-547`).
- **Meta keys a run writes** (JSON `meta`, none of them verdict data): `in_reply_to`, the customer text ids a reply answers (`RunFrontDesk.php:359`, `:1149`; read by `ConversationThread::customerWroteAgain`, `ConversationThread.php:161`, and by the model's Already-with-the-owner section, `FrontDeskPrompt.php:244`); `parts`, above; `price_sentences`, one entry per sentence that went out, naming the service, the sentence key and its amounts in cents (`priceSentencesMeta`, `RunFrontDesk.php:1103-1109`, through `codeSentencesMeta` `:1119-1125`); `offers`, the slugs of offer sentences in the text (`:1123`); `price_pending`, the services still waiting on the customer's intake answers, read back by the next run (`:359`, read at `:1067-1081`); `price_slugs` and `price_open`, the services the run looked a price up for and those of them with no sentence (`priceLookups`, `:428-436`); `replaces`, the ids of drafts a newer draft withdrew (`:1518`, `:1526`); `first_reply`, on a whole-thread draft, the first reply's words and its hold reason (`:576`); `held_sentences`, below; and `answered_by`, above.
- **The label guard.** While a draft waits behind a booking question, only a faq answer or an intake question may send beside it (`labelGuardFor`, `RunFrontDesk.php:446-449`). The guard is recorded on the verdict as `checks.label.guard` and `guard_passed` (`DecideSendOrDraft.php:76-81`), and a reply whose label is not on it is held as `waiting_guard:<label>` (`:93`).
- **Verdict.** Built by `DecideSendOrDraft::decide` (`DecideSendOrDraft.php:54`): label check, then the guard when one applies, then length, then the code checks (the first finding that fails is the veto, `:91-97`), then Jev asked once about the words, vetoed or not, and Jev can only hold, never rescue (`:21-26`, `:99-121`). A reply with no model words, such as a price the owner has not quoted, is held by `holdWithoutWords` (`:129`), which records that the label, length and code checks did not run. Each of Jev's price, promise, discount and complaint answers is judged against its own bar, `price_max_yes`, `promise_max_yes`, `discount_max_yes` and `complaint_max_yes` in the classifier array of `config/gate.php:71-80` (D-56: price and discount 0.075, promise and complaint 0.15), read in `TriageReading::read` (`TriageReading.php:61-65`); the whole array is stored on the verdict as `thresholds` (`DecideSendOrDraft.php:86`). Stored through `Verdict::toAttributes` (`Verdict.php:89`). The classifier is bound at `AppServiceProvider.php:47`; tests swap in `FakeClassifier` (`tests/Pest.php:61`).
- **The run's reading, `gate.customer_reading`.** Beside the words check (`gate.checks.classifier`), every verdict stores the one Jev reading of the customer's own text that the run made before it did anything else (`DecideSendOrDraft.php:74` in `decide()`, `:138` in `holdWithoutWords()`; a fixed line stores it too, `SendFixedReply::fixedGate`, `SendFixedReply.php:114-122`; and the reading is stored on the safety line when Jev's reading or a words check sends it, as `gate.customer_reading` beside `gate.life_safety` (trigger `classifier`, `SendLifeSafetyLine.php:105-110`; the keyword and agent-triggered lines carry none, G-02.1-3)). It holds whether Jev was asked and whether the call failed, an error, the model, the answers and the reading (`CustomerReading::toArray`, `CustomerReading.php:161-172`). A reading that never ran, such as when no business folder is live, is stored marked missing, not failed: it reads back as missing (`fromStored`, `:79-94`) and counts as no reading at all for the sender (`fromStoredIfMade`, `:101-106`). Its complaint, danger and request-for-a-person answers can hold, hand off or send the safety line; its price, promise and discount answers are recorded and never acted on (`CustomerReading.php:8-10`). A words check can add a hold, never clear what the reading found: a failed or missing reading holds words that would send as `classifier_failed`, and an unsure request for a person as `classifier_unsure:asks_for_person` (`DecideSendOrDraft.php:113-119`).
- **Price alone needs evidence.** `HeldReasons::priceAlone` (`HeldReasons.php:49-72`) says a draft was held on price and nothing else only when every recorded check agrees: a price reason code (`PRICE_CODES`, `:22`), the length check not failed, only price findings from the code check, the label check not failed (or failed only because the label was price), no recorded label of promise, discount or complaint, whether that check passed, failed or never ran (WR-03, `recordedLabelNeverGoesAlone` `HeldReasons.php:78`), the stored customer reading ran, did not fail and found no complaint, danger or request for a person (`:181-193`), and, when the draft holds model words, a words check that ran and found only price reasons, no danger and no request for a person (`:200-224`). A check that did not run, failed or is missing counts as disagreement (CR-02), so a draft stored before the reading was kept, or with a malformed verdict, stays with the owner.
- **Held sentences and pre-filled drafts.** When code knew the owner's price or offer sentences and they did not go out (a complaint, a failed, missing or unsure reading, a promise label on blank words, a danger, a send the sender refused, or a partial holding line that was to carry them and could not go out, `keepUnsentSentences` `RunFrontDesk.php:1579`, IN-03), the draft body is the held words, a blank line and the sentences exactly as code would have sent them (`prefilledBody`, `RunFrontDesk.php:1602-1612`), and `meta.held_sentences` lists them (`storeDraft`, `:1505-1507`), so the owner can send the answer with one tap (D-44).
- **The sender's reading check (second chokepoint).** `OutboundSender` refuses an automated text that lacks what its gate must carry, so no path can skip the run's reading (`OutboundSender.php:39-43`, `refuseWithoutReading` `:327-342`, called for automated sends only, `:203-205`). What each kind of text needs is `whyReadingBlocks` (`:349-370`, D-49): owner sentences need a reading that ran, did not fail and found no complaint (`CustomerReading::allowsOwnerSentences`, `CustomerReading.php:121`); the model's words need their own words check to have passed and a reading that ran and did not fail (`whyModelWordsAreBlocked`, `OutboundSender.php:409-428`); a fixed line needs only the reading record, a failed one included, because it promises nothing (`partsOf`, `:384-400`); a combined-text kind that arrives without `meta.parts` needs what both owner sentences and model words need (`:397`, IN-10). A combined text needs what each part needs. A reading marked missing counts as none (`readingOf`, `:435-440`). The safety line (origin `LifeSafety`) and the owner's own sends are never asked for a reading, and an approved draft goes through `sendExisting`, which does not ask either (`:203`, `:226-263`). A refused send is never sent and the owner is told: no reading at all raises `safety_check_missing`, always right away and once per customer text, and a part lacking something else raises `front_desk_failed` on the folder's timing (`:335-339`, `alertAboutRefusal` `:447-459`).
- **Hold reason codes**, with the words the owner reads (`Verdict.php:131-147`): `price:no_sentence`, no price on file, raised when a price question has no sentence code can send (`RunFrontDesk.php:287`, `:313-314`), usually with owner words naming the services (`noPriceReason`, `:1176-1192`; a hold takes such words through `Verdict.php:53` and `:71` and the code stays the same); `discount:no_live_offer`, no offer running today (`RunFrontDesk.php:284`, `:315-316`); `touches_waiting`, a reply that adds to the question the owner already holds is never sent (`:526`); `waiting_guard:<label>`, above; `agent:possible_danger`, the agent's own third-net flag, read "Held: may be urgent" (`Verdict.php:139-142`, raised by `codeHoldReason` at `RunFrontDesk.php:1628` and on the verdict at `:302`); and `classifier:complaint`, a complaint in the run's reading, which stops the owner's sentences and holds the words (`codeHoldReason` `RunFrontDesk.php:1623`, on the verdict `:319-321`). `HeldReasons::PRICE_CODES` (`HeldReasons.php:22`) lists the codes that mean a draft was held on price alone, and `SendFixedReply::COMPLAINT_CODES` (`SendFixedReply.php:34`) the codes that mean a complaint.

## Words on this card
"Draft" means status `draft` only; a draft the owner approves is the same row, no longer a draft. "Send rule" is the code in `app/SendRule/`; "sending rules" is the owner's file `rules/sending.md` (`ActiveConfig.php:98`), an input to it. The SDK class `Laravel\Ai\Messages\Message` (`FrontDeskPrompt.php:15`, imported as `AiMessage`) is a different thing: the turns handed to the model, not a row. "Answered" is a draft ending chosen by code, never the owner. "Reading" is Jev's one look at the customer's own text for a run (`gate.customer_reading`); the "words check" is Jev's look at one set of the agent's words (`gate.checks.classifier`).
