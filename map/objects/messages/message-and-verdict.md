# Message and its verdict

**Type:** object · **Mark:** live · **Checked:** 2026-10-14 @ c48491d · **Where:** `app/Models/Message.php:44`, `app/SendRule/Verdict.php:15`

**One sentence.** A `messages` row is one text or form post in a conversation, either direction; on an automated reply it also holds the send rule's verdict: `gate_outcome`, `gate_reason` and the `gate` JSON (code name `gate*`, prose name "verdict").

**Why this shape.** One row carries the customer's text, or the agent's words, the owner's decision on them and the delivery, so a draft is never copied or deleted (D-54, D-28). The verdict lives on the message because it is the calibration data later tuning learns from; `gate.version` lets a new shape sit beside the old (D-07, `DecideSendOrDraft.php:56`).

- **Answered (new in Phase 02.1).** Answered is the one ending the owner does not choose: code closes the draft because a text carrying the owner's price sentence went out for the services the draft was still waiting on (`ResolveDraft::closeAsAnswered`, `ResolveDraft.php:124`, called through `RunFrontDesk.php:299`). - `kind` is what the system sent it as (`app/Enums/MessageKind.php:8`); `label` is what the agent called its reply, one of eight words (`app/Enums/ReplyLabel.php:9`). `MessageAuthor::Agent` marks every automated text, fixed ones included (`MessageAuthor.php:8`). Besides the agent's reply, the holding, hand-off and safety lines, there are now six kinds code assembles or chooses: the partial holding, complaint, discount, check-in and added-info lines and the code answer, which is the owner's price or offer sentences sent by code (`MessageKind.php:10-31`).
- **Which kinds start a wait.** The holding reply and the partial, complaint and discount holdings tell the customer the owner will answer, so they start a wait (`MessageKind::startsWait`, `MessageKind.php:39-42`). `SendFixedReply::holdingAlreadySent` (`SendFixedReply.php:118`) finds the newest message of those kinds (`:120-124`); the wait is over only when an owner text went out after it (`:134-138`) or a draft was approved, edited, discarded or closed as answered since it (`:139-141`). Automated texts, a check-in line, an added-info line, a code answer or an agent reply among them, never end it (`:115-116`). That is why a customer who texts again while the owner has not answered gets no second holding reply. `MessageKind::assembledByCode` (`MessageKind.php:50`) lists the kinds code puts together from owner sentences and fixed lines.
- **One path for code-assembled texts.** `SendCombinedReply::handle` (`SendCombinedReply.php:35`) takes the parts of one text (`ReplyParts`: an optional complaint line, the owner's sentences, the model's words that passed the send rule, one fixed line, joined in that order, `ReplyParts.php:28-36`), picks the kind from them (`ReplyParts.php:42`, `SendCombinedReply.php:37`), records the part names in `meta.parts` (`SendCombinedReply.php:42`, names set at `ReplyParts.php:58`), and sends through `OutboundSender` (`SendCombinedReply.php:56`). With no model words in it, the text is code's own, so it gets a fixed-reply verdict and no classifier (`:46-54`). `composedLength` (`:68`) measures the text as the customer would get it; over 1,600 characters (`SendOwnerReply.php:20`) the model's words are held as `too_long`, kept as a draft, and the sentences go on their own with the partial holding line (`RunFrontDesk.php:264-266`, `:426-428`).
- **Meta keys a run writes** (JSON `meta`, none of them verdict data): `in_reply_to`, the customer text ids a reply answers (`RunFrontDesk.php:252`; read by `ConversationThread::customerWroteAgain`, `ConversationThread.php:161`, and by the model's Already-with-the-owner section, `FrontDeskPrompt.php:243`); `parts`, above; `price_sentences`, one entry per sentence that went out, naming the service, the sentence key and its amounts in cents (`RunFrontDesk.php:761-767`, `:777-782`); `offers`, the slugs of offer sentences in the text (`:781`); `price_pending`, the services still waiting on the customer's intake answers, read back by the next run (`:252`, read at `:726-738`); `price_slugs` and `price_open`, the services the run looked a price up for and those of them with no sentence (`:318-326`); `replaces`, the ids of drafts a newer draft withdrew (`:1025`, `:1033`); `first_reply`, on a whole-thread draft, the first reply's words and its hold reason (`:457`); and `answered_by`, above.
- **The label guard.** While a draft waits behind a booking question, only a faq answer or an intake question may send beside it (`RunFrontDesk.php:336-339`). The guard is recorded on the verdict as `checks.label.guard` and `guard_passed` (`DecideSendOrDraft.php:61-66`), and a reply whose label is not on it is held as `waiting_guard:<label>` (`:78`).
- **Verdict.** Built by `DecideSendOrDraft::decide` (`DecideSendOrDraft.php:40`): label check, then the guard when one applies, then length, then the code checks, then Jev asked once, and Jev can only hold, never rescue (`:21-22`, `:76-82`, `:88`). A reply with no model words, such as a price the owner has not quoted, is held by `holdWithoutWords` (`:96`), which records that the label, length and code checks did not run. Each of Jev's price, promise, discount and complaint answers is judged against its own bar, `price_max_yes`, `promise_max_yes`, `discount_max_yes` and `complaint_max_yes` in the classifier array of `config/gate.php:71-80` (D-56: price and discount 0.075, promise and complaint 0.15), read in `TriageReading::read` (`TriageReading.php:61-65`); the whole array is stored on the verdict as `thresholds` (`DecideSendOrDraft.php:71`). Stored through `Verdict::toAttributes` (`Verdict.php:89`). The classifier is bound at `AppServiceProvider.php:47`; tests swap in `FakeClassifier` (`tests/Pest.php:61`).
- **New hold reason codes**, with the words the owner reads (`Verdict.php:131-140`): `price:no_sentence`, no price on file, raised when a price question has no sentence code can send (`RunFrontDesk.php:204`, `:223`), usually with owner words naming the services (`noPriceReason`, `:830`; a hold takes such words through `Verdict.php:53` and `:71` and the code stays the same); `discount:no_live_offer`, no offer running today (`RunFrontDesk.php:201`, `:225`); `touches_waiting`, a reply that adds to the question the owner already holds is never sent (`:409`); and `waiting_guard:<label>`, above. `HeldReasons::PRICE_CODES` (`HeldReasons.php:21`) lists the codes that mean a draft was held on price alone.

## Words on this card
"Draft" means status `draft` only; a draft the owner approves is the same row, no longer a draft. "Send rule" is the code in `app/SendRule/`; "sending rules" is the owner's file `rules/sending.md` (`ActiveConfig.php:98`), an input to it. The SDK class `Laravel\Ai\Messages\Message` (`FrontDeskPrompt.php:15`, imported as `AiMessage`) is a different thing: the turns handed to the model, not a row. "Answered" is a draft ending chosen by code, never the owner.
